# Task Service

> **Версия:** 6.0

Task Service — микросервисное backend-приложение для управления задачами, разработанное на **Spring Boot**. Проект демонстрирует построение современной backend-архитектуры с использованием **Kafka**, **Keycloak**, **PostgreSQL**, **Docker** и **Testcontainers**.

## Возможности

- REST API
- JWT-аутентификация и авторизация (Keycloak)
- Управление задачами
- Хранение данных в PostgreSQL
- Миграции базы данных с Flyway
- Асинхронное взаимодействие сервисов через Kafka
- Docker Compose окружение
- Интеграционные тесты с Testcontainers
- API Gateway
- Микросервисная архитектура

# Архитектура сервисов

Проект состоит из нескольких микросервисов:

| Сервис | Назначение |
|---------|------------|
| **API Gateway** | Единая точка входа, маршрутизация, проверка JWT по ключам Keycloak (JWKS) и роли `worker` |
| **Auth Service** | Регистрация, авторизация пользователей, интеграция с Keycloak |
| **Task Service** | Управление жизненным циклом задач |
| **Accounting Service** | Начисление выплат за выполненные задачи |
| **Search Service** | Хранение поисковой модели и нечеткий поиск работников |

Общие контракты событий Kafka (record'ы и имена топиков) лежат в модуле **event-contracts**.

## Надёжность обмена событиями

- **task-service → Kafka**: события публикуются после коммита транзакции БД.
- **auth-service → Kafka**: оба события регистрации уходят в одной Kafka-транзакции; если отправка не удалась,
  пользователь удаляется из Keycloak (компенсация) и клиент получает `503`.
- **accounting-service → Kafka**: платежи отправляются через outbox-таблицу `payment` (раз в 10 секунд).
- **Консьюмеры**: повторы с экспоненциальной задержкой (1-2-4-8 с), затем запись уходит в dead letter topic
  `<топик>.<consumer-group>.DLT` с заголовками исходного топика, offset и исключения.
  Посмотреть: `docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic user-flow.accounting-service.DLT --from-beginning --property print.headers=true`
- **Идемпотентность**: все обработчики событий безопасны при повторной доставке (upsert, inbox по `payment_id`).
- **Порядок событий** из разных топиков не важен: search не держит внешних ключей между проекциями,
  accounting создаёт job по `TaskFinishedEvent`, даже если `WorkerAssignedEvent` ещё не пришёл.

## Известные ограничения

- Балансы в search-service - копия данных accounting-service (источник правды) и обновляются с задержкой.
- Если коммит Kafka-транзакции в auth-service завершился таймаутом, но на брокере прошёл, пользователь будет
  удалён компенсацией, а события останутся. Полностью закрыть это можно только outbox-таблицей в собственной БД.
- Если выплата пропущена (сервис не работал в платёжную пятницу), всё накопленное оплачивается в следующую.

# Функциональные возможности

### Task Service

- получение списка задач с пагинацией;
- получение задачи по идентификатору;
- создание новой задачи;
- назначение исполнителя;
- изменение статуса задачи.

### Accounting Service

- хранение балансов работников;
- автоматическое начисление выплат за завершённые задачи;
- выполнение начислений по расписанию: через одну пятницу в 00:00 по часовому поясу контейнера (`TZ`). Первая выплата - в ближайшую пятницу после первого старта сервиса или в дату `ACCOUNTING_PAYOUT_ANCHOR_DATE`.

### Search Service

- получение работников;
- получение задач;
- получение балансов;
- нечеткий поиск работников по email.

# Запуск проекта

## Предварительные требования

- Docker
- Docker Compose
- Java 21

## Запуск

```bash
cp .env.example .env   # при необходимости поменять значения
docker compose up -d
```

Realm `demo` импортируется из `keycloak/realm/demo-realm.json` при первом старте Keycloak
(уже существующий realm не перезаписывается - для повторного импорта нужен `docker compose down -v`).
В нём уже настроено:

- клиент `auth-service` с ролью `manage-users` у service account;
- роль `worker`, которую автоматически получает каждый зарегистрированный пользователь.

Все запросы, кроме `/registration` и `/login`, требуют JWT с ролью `worker`.

## Тесты

```bash
./gradlew test
```

Интеграционные тесты поднимают PostgreSQL и Kafka через Testcontainers, поэтому нужен запущенный Docker.

## Task Service

### Управление задачами

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/tasks?page={page}&size={size}` | Получить страницу задач |
| GET | `/api/tasks/{taskId}` | Получить задачу по ID |
| POST | `/api/tasks` | Создать задачу |
| PATCH | `/api/tasks/{taskId}/executor?workerId={uuid}` | Назначить исполнителя |
| PATCH | `/api/tasks/{taskId}/status?status={NEW\|IN_PROGRESS\|FINISHED\|CANCELLED}` | Изменить статус задачи |

# История версий

## 6.0
- Исправлено начисление выплат: оплачивается каждая завершённая задача, а не одна на работника.
- Выплаты через одну пятницу; outbox платежей раз в 10 секунд.
- Повторы и dead letter topics для всех консьюмеров Kafka; события больше не теряются молча.
- Порядок событий из разных топиков больше не влияет на результат.
- Компенсация регистрации в auth-service и Kafka-транзакции.
- Валидация запросов (400), правила статусов задач, optimistic lock (409).
- Проверка JWT в gateway локально по JWKS, роль `worker`, секреты вынесены в `.env`.
- Healthcheck'и и порядок запуска в Docker Compose, облегчённые Docker-образы.
- Общий модуль контрактов событий `event-contracts`; удалены Kotlin и неиспользуемые зависимости.

## 5.0
- Добавлен **Accounting Service** с автоматическим начислением выплат за завершённые задачи.
- Добавлен **Search Service**, агрегирующий данные из системы и предоставляющий API нечеткого поиска по email.
